上板实验 01　/　Windows x64 · PowerShell · ST-LINK

把 threadx_core 跑在 NUCLEO-G474RE 上

从安装交叉编译器开始，亲手生成板级固件。最后不靠灯、不靠串口：从芯片里读回程序，再观察八个线程的计数是否都在增加。

不用导入 CubeIDE 工程，不用 CubeMX、CMake、Ninja、OIL 或 DTS。第 1–3 步可以不插开发板；只有你手动执行第 5 步并确认才会写 Flash；打开本页不会安装软件或操作板子。

只打算阅读源码？跳过工具安装，去不接板的内核阅读路线。

01 / 准备

需要装什么？

已有 STM32CubeIDE？先不要重装。这次只用它附带的 GNU 编译器及烧录工具，不打开 IDE 也能做完。

① Python 3（Windows x64）　Python 官方下载
选 Windows 64 位安装器或官方安装管理器，确保安装了 Python 运行时和 py 命令。脚本只用标准库，无须 pip install。教程实测 Python 3.12.10；已有受支持的 Python 3.12 或更新版本可先复用。
② GNU Tools for STM32　STM32CubeIDE 官方下载
从零安装时选 Eclipse 版、Windows x86-64、2.2.0（不是 VS Code 扩展或 Clang）。下载后解压并运行安装程序。该版提供本例用的 arm-none-eabi-gcc、ar、nm、objcopy 和 C 运行库；对照 ST 2.2.0 发布说明。已有其他 IDE 版本也可用，只要下节查出的 ST GCC 构建号完全相同。
③ G4 板级文件　ST 官方 X-CUBE-AZRTOS-G4 v2.0.0
在发布页下载 Source code (zip)，完整解压，保留 Drivers 与 Projects 的相对位置。它提供 ST 启动汇编、系统初始化、链接脚本和 CMSIS 头；不使用包里的 ThreadX 内核，也不运行 ST 的 Tx_Thread_Sync 应用。已有匹配的解压目录可直接用，不必再装包管理器。
④ STM32CubeProgrammer　ST 官方下载
烧录才需要，实测 CLI v2.23.0。IDE 的 plugins 下已有该版 STM32_Programmer_CLI.exe 就跳过安装；没有则安装独立 Windows x64 版，稍后选安装目录 bin 下的程序。命令含义见 2.23.0 官方 CLI 手册。
仅当探针未识别：ST-LINK Windows USB 驱动（STSW-LINK009）
先确认使用 USB 数据线；需要时按包内说明装驱动，拔插一次再查。板载 STLINK-V3E，不需要另买探针或 USB 转串口。
如果是新电脑：安装顺序与每一步的完成标志
  1. Python：从上方 Python 官网选普通 Windows installer (64-bit)，不要选 embeddable ZIP。传统安装器保留 Python Launcher，完成后重新开 PowerShell；输入 py -3 --version 应显示 Python 3 的版本号。若改用新版 Python install manager，先按官方 Windows 指南添加一个 Python 3 运行时。
  2. CubeIDE：在 ST 下载页选择 Eclipse 版 2.2.0 的 Windows x86-64 安装包，解压、运行安装程序并记下安装位置。安装完成的标志不是成功 Import，而是目录内有 plugins，且能在第 2 步查到正确 GCC。ST 安装文档目录：选择 UM2563。
  3. 板级包：解压 v2.0.0 的 ZIP；打开到同时看见 Drivers、Projects 的那层，复制该目录路径。这一步不是运行安装器。
  4. 烧录器：IDE 2.2.0 已内带 CLI 时不做任何事。只有确实缺少它时才到官方页面选 Windows 64 位安装包，解压运行安装程序，保留默认组件；安装好记下 bin/STM32_Programmer_CLI.exe。ST 官方安装说明。驱动仅在需要时补装。

要准备的是两份目录：一份是本学习仓库（有 threadx_core），另一份是 ST 的板级包（有 Drivers）。只有后者，编译不了本教程的裁剪内核。

02 / 环境自检

在同一个 PowerShell 窗口里设置路径

在资源管理器打开 threadx-core-g474re 仓库根目录，从这里打开 PowerShell。不要在 threadx_core 里面执行。已有本仓库直接用；首次获取请运行 git clone https://github.com/OsakaKasugaAyumu/threadx-core-g474re.git，然后进入 threadx-core-g474re。仓库属性保留源码原字节；不要用编辑器批量转换换行。不需要特意把工具加到系统 PATH。下面每个命令框按顺序单独执行：本步报错就停，不要跳到写入步骤。

. {
  $ErrorActionPreference = 'Stop'
  $repo = (Get-Location).Path
  if (!(Test-Path -LiteralPath '.\threadx_core\autoconf.h') -or
      !(Test-Path -LiteralPath '.\demo_threadx\core\examples\build_g474re.py')) {
    throw '请进入含裁剪版和本教程的仓库根目录；不要用旧版 main 代替。'
  }
  py -3 --version
  if ($LASTEXITCODE -ne 0) { throw '未找到 Windows Python 3 运行时' }
  $ide = Join-Path (Split-Path $repo -Parent) 'threadx_build\tools\STM32CubeIDE'
  if (!(Test-Path -LiteralPath (Join-Path $ide 'plugins'))) {
    $ide = (Read-Host '输入 STM32CubeIDE 安装目录（这一层直接含 plugins）').Trim('"')
  }
  $g = @(Get-ChildItem -Path (Join-Path $ide 'plugins\*gnu-tools-for-stm32.14.3.rel1*\tools\bin\arm-none-eabi-gcc.exe') -File -ErrorAction SilentlyContinue)
  if ($g.Count -eq 1) { $gcc = $g[0].FullName }
  else { $gcc = (Read-Host '输入指定版本 arm-none-eabi-gcc.exe 完整路径').Trim('"') }
  & $gcc --version
  & $gcc -dumpmachine
  $cube = (Read-Host '输入 ST 板级包解压根目录（这一层直接含 Drivers、Projects）').Trim('"')
  $stFiles = @('Drivers\CMSIS\Include\core_cm4.h', 'Drivers\CMSIS\Device\ST\STM32G4xx\Include\stm32g474xx.h', 'Projects\NUCLEO-G474RE\Applications\ThreadX\Tx_Thread_Sync\STM32CubeIDE\STM32G474RETX_FLASH.ld')
  foreach ($f in $stFiles) { if (!(Test-Path -LiteralPath (Join-Path $cube $f))) { throw "未找到 $f；检查是否多套了一层解压目录" } }
}

通过标志：目标为 arm-none-eabi；版本行含 GNU Tools for STM32 14.3.rel1.20251027-0700 和 14.3.1 20250623。不要用 PC 上的 MinGW/Cygwin GCC；同为“14.3”的不同发行包也不等于这条基线。

03 / 不用连接硬件

从裁剪源码生成板级 ELF 和镜像

编译命令中的三个参数分别是 --gcc（编译器）、--cube-root（ST 板级包）和 --out（本次新建的输出目录）。运行教程配套的只编译脚本。它从 threadx_core/autoconf.h 和 threadx_core/demo_threadx.c 出发，不从 main 读源码，不借旧的 libthreadx.a，也没有调用烧录器的代码。

. {
  $out = Join-Path $repo ('build\learn-g474re-' + [guid]::NewGuid().ToString('N').Substring(0,8))
  py -3 -B .\demo_threadx\core\examples\build_g474re.py --gcc "$gcc" --cube-root "$cube" --out "$out"
  if ($LASTEXITCODE -ne 0) { throw '编译或镜像检查失败，到此停止；不要使用残留产物。' }
  $elf = Join-Path $out 'demo_threadx_g474re.elf'
  $bin = Join-Path $out 'demo_threadx_g474re.bin'
  Get-Item -LiteralPath $elf,$bin | Select-Object Name,Length
  Get-FileHash -LiteralPath $bin -Algorithm SHA256
}

编译通过标志：最后一行组应有 PASS，BIN 为 14,912 字节。.elf 给调试器、符号查询用；.map 看谁被链接；.hex 自带地址；.bin 是裸字节，稍后写入必须显式给 0x08000000。本页只用文件名带 g474re 的板级产物，绝不烧通用 gnu-m4f/demo_threadx.elf。

为什么有两种已知哈希？换目录是不是编错了？
  • C5 image：原验收工作区默认生成此版。BIN SHA-256：c0f9fd038cadc423d0768cf7d126de85cbddc35019989d0584260f8d064d9674；这是曾在板上读回并实测的字节。
  • portable image：新位置自动用等长的公共诊断路径，也可显式加 --portable。SHA-256：07fd53b3a69a61442d3082700eaeb7ed62c705b2b751933ed58f9ebae60654ff。两份 BIN 已逐字节比较：仅三处异常诊断的 __FILE__ 路径前缀不同；指令、向量、链接地址及其余数据未变。此版已从干净目录编译，不是旧 C5 日志中的那次烧录；运行结果以自己第 6 步为准。

不要拿整个 ELF 的哈希判断二者；ELF 还包含本地调试路径。未知 BIN 哈希一律停止，不用修改脚本中的期望值来放行。

它如何从通用 Demo 变成 G474RE 固件？原来两个构建脚本呢？

应用和内核用 -mcpu=cortex-m4 -mthumb -mfpu=fpv4-sp-d16 -mfloat-abi=hard；C 用 -O1。板级用 ST 的 startup_stm32g474retx.s、system_stm32g4xx.c、STM32G474RETX_FLASH.ld 和本仓库的 board_threadx.c：HSI16、100 Hz SysTick，PendSV 由 M4 端口提供。没有把通用 crt0、通用向量表或通用低层初始化混进来。tx_misra.S 与 tx_misra.c 分别编译，只有汇编提供者进内核库。

build_nucleo_g474re.py 默认重建未裁剪的 main，不是本教程入口。build_core_c3.py + verify_core_c3.py 是双目标等价性审计，要原机的锁定基线、命令库和产物；干净克隆没有这些文件是正常的。教程入口只构建板级目标，不冒充重新完成全套 C3 审计。查看已有 C3 验收。

04 / 识别与备份

先认出你的板，再谈烧录

仅接一块 NUCLEO-G474RE。用数据线接板载 ST-LINK 的 CN1，关闭占用探针的 CubeIDE 调试会话和 CubeProgrammer GUI。这里找的是 SWD 探针，不是 COM 端口。可对照 ST 板卡手册 UM2505。

展开命令：列出唯一探针，检查板名、芯片与 Flash 配置
. {
  $probeReady = $false; $backupReady = $false; $verifiedOnBoard = $false
  $p = @(Get-ChildItem -Path (Join-Path $ide 'plugins\*cubeprogrammer*\tools\bin\STM32_Programmer_CLI.exe') -File -ErrorAction SilentlyContinue)
  if ($p.Count -eq 1) { $cli = $p[0].FullName }
  else { $cli = (Read-Host '输入 STM32_Programmer_CLI.exe 完整路径').Trim('"') }
  function Call-St([string[]]$Argv) {
    $lines = & $cli @Argv
    if ($LASTEXITCODE -ne 0) { throw ("CubeProgrammer 失败：`n" + ($lines -join "`n")) }
    $lines
  }
  function Get-OneProbe {
    $r = (Call-St @('-l','st-link')) -join "`n"
    $ids = [regex]::Matches($r,'(?im)^\s*ST-LINK SN\s*:\s*([0-9a-f]+)\s*$')
    if ($ids.Count -ne 1 -or $r -notmatch '(?im)^\s*Board Name\s*:\s*NUCLEO-G474RE\s*$') {
      throw "需要且只能有一块已识别的 G474RE：`n$r"
    }
    return $ids[0].Groups[1].Value
  }
  function Read-HexWord([string]$Text,[string]$At) {
    $m = [regex]::Match($Text, '(?im)^\s*'+[regex]::Escape($At)+'\s*:\s*([0-9a-f]{8})\b')
    if (!$m.Success) { throw "未读到 $At，停止" }; return [Convert]::ToUInt32($m.Groups[1].Value,16)
  }
  $v = (Call-St @('-version')) -join "`n"; $v
  if ($v -notmatch '\b2\.23\.0\b') { throw '本教程命令与解析按 CubeProgrammer 2.23.0 验证，请选该版本。' }
  $sn = Get-OneProbe
  $hot = @('-c','port=SWD',"sn=$sn",'mode=HOTPLUG','freq=4000')
  $ur = @('-c','port=SWD',"sn=$sn",'mode=UR','freq=4000')
  $id = (Call-St ($hot + @('-r32','0x40022020','4','-score'))) -join "`n"; $id
  if ($id -notmatch '(?im)^\s*Board\s*:\s*NUCLEO-G474RE\s*$' -or $id -notmatch '(?im)Device ID\s*:\s*0x0*469\b' -or $id -notmatch '(?im)(NVM|Flash) size\s*:\s*512\s*KBytes') { throw '板名、器件 ID 或 Flash 容量不符，停止' }
  $optr = Read-HexWord $id '0x40022020'
  if (($optr -band 0xff) -ne 0xaa -or ($optr -band 0x400000) -eq 0 -or ($optr -band 0x100000) -ne 0) { throw '不是预期的无读保护、双 Bank、非 Bank2 启动配置；不要改选项字节。' }
  $probeReady = $true
}

下面把即将涉及的 8 页与其后 1 页备份到个人本地目录，不进 Git。双 Bank 模式页大小是 2 KiB；14,912 字节的镜像结束在 0x08003A3F，但最后一个擦除页还剩 1,472 字节。上次实板该处并不全是 FF，所以不能只把裸 BIN 拖进去就算完成。页模式见 ST 参考手册 RM0440，Flash memory 一章。

展开命令：只读备份，写入前可以停在这里
. {
  $backupReady = $false
  if (!$probeReady) { throw '先通过上述板型和 Flash 配置检查。' }
  $image = [IO.File]::ReadAllBytes($bin)
  $allowed = @('c0f9fd038cadc423d0768cf7d126de85cbddc35019989d0584260f8d064d9674',
               '07fd53b3a69a61442d3082700eaeb7ed62c705b2b751933ed58f9ebae60654ff')
  $imgHash = (Get-FileHash -LiteralPath $bin -Algorithm SHA256).Hash
  if ($image.Length -ne 14912 -or $imgHash -notin $allowed) { throw '不是第 3 步已知的板级 BIN。' }
  if ((Get-OneProbe) -ne $sn) { throw '探针发生变化。' }
  $save = Join-Path $env:LOCALAPPDATA ('ThreadX-Learn\backup-' + [guid]::NewGuid())
  $null = New-Item -ItemType Directory -Path $save -Force
  $before = Join-Path $save 'before-pages-and-guard.bin'
  Call-St ($hot + @('-u','0x08000000','0x4800',$before))
  $old = [IO.File]::ReadAllBytes($before)
  if ($old.Length -ne 0x4800) { throw '未读满 9 页；不要写。' }
  $backupReady = $true; "局部备份：$before"
}

到此没有写 Flash。这不是全片备份。如果板上有不能丢的其他固件，先停止；需要保留完整旧程序时，可在已确认 512 KiB、无读保护后，另将 Call-St ($hot + @('-u','0x08000000','0x80000',(Join-Path $save 'full-flash.bin'))) 读到本地，确认长度为 524,288 字节。不要上传备份或包含探针序列号的原始输出。

05 / 唯一的写入步骤

写应用页，独立读回，再复位

这一步会覆盖已有应用。确认这是自己的 G474RE 学习板、可以停机、可覆盖从 0x08000000 开始的程序，再执行。不会整片擦除，不改 Option Bytes。只有本节中的 -w 会写 Flash；写入或校验报错就停，不要用解除读保护或全擦来试。

展开手动烧录命令（执行时还要输入板名确认）
. {
  $verifiedOnBoard = $false
  if (!$backupReady -or (Get-OneProbe) -ne $sn) { throw '先完成同一块板的备份。' }
  if ((Read-Host '确认覆盖应用请输入 G474RE，否则退出') -cne 'G474RE') { throw '已取消，未写入。' }
  if ((Get-FileHash -LiteralPath $bin -Algorithm SHA256).Hash -ne $imgHash) { throw '镜像已变化。' }
  $locked = Join-Path $save 'before-write.bin'
  $lockInfo = (Call-St ($hot + @('-halt','-r32','0x40022020','4','-u','0x08000000','0x4800',$locked))) -join "`n"
  if ((Read-HexWord $lockInfo '0x40022020') -ne $optr) { throw 'Flash 配置已变化；已停核但未写入。' }
  function Equal-Bytes([byte[]]$A,[byte[]]$B) {
    if ($A.Length -ne $B.Length) { return $false }
    for ($i=0; $i -lt $A.Length; $i++) { if ($A[$i] -ne $B[$i]) { return $false } }; return $true
  }
  if (!(Equal-Bytes $old ([IO.File]::ReadAllBytes($locked)))) { throw '板上内容与备份不同；已停核且未写，请检查。' }
  $expect = [byte[]]$old.Clone(); [Array]::Copy($image,0,$expect,0,$image.Length)
  $transfer = Join-Path $save 'image-plus-original-tail.bin'
  [IO.File]::WriteAllBytes($transfer,[byte[]]$expect[0..0x3fff])  # 8 页；不写第 9 页
  Call-St ($ur + @('-w',$transfer,'0x08000000','-v'))
  $again = Join-Path $save 'after-pages-and-guard.bin'
  Call-St ($hot + @('-u','0x08000000','0x4800',$again))
  if (!(Equal-Bytes $expect ([IO.File]::ReadAllBytes($again)))) { throw '读回不一致；不要运行、不要重复烧写。' }
  $verifiedOnBoard = $true
  '读回通过：14,912 字节镜像一致，1,472 字节页尾和随后 2,048 字节均未变。'
  Call-St ($hot + @('-hardRst','-run','-score'))
  Start-Sleep -Milliseconds 400
  Call-St ($hot + @('-score'))
}

通过标志：-v 成功、独立读回逐字节一致，最后单独查询显示 Core is running。刚复位那一瞬间偶尔报告 Reset；先无复位地查询状态，不要重复写。到这只说明“程序写对了”，还不能证明八个线程都在运行。

06 / 冒烟测试

不用串口，直接看 8 个线程和队列

用本次同目录里的 ELF取符号地址，每隔约两秒读一组。采样时短暂停核，让所有计数是同一时刻的快照；读完恢复运行，两个样本之间不复位。下面不会写 Flash。

展开采样命令：读取 ELF 里的符号并比较三组快照
. {
  if (!$verifiedOnBoard -or (Get-OneProbe) -ne $sn) { throw '请先通过本次烧录读回。' }
  $nm = Join-Path (Split-Path $gcc -Parent) 'arm-none-eabi-nm.exe'
  $watch = @('_tx_timer_system_clock') + @(0..7 | ForEach-Object { "thread_${_}_counter" }) + @('thread_1_messages_sent','thread_2_messages_received')
  $addr = @{}; $listing = & $nm -n --defined-only $elf
  if ($LASTEXITCODE -ne 0) { throw 'ELF 符号表不可读。' }
  foreach ($line in $listing) {
    if ($line -match '^([0-9A-Fa-f]{8})\s+\w\s+(\w+)$' -and $matches[2] -in $watch) { $addr[$matches[2]] = '0x'+$matches[1] }
  }
  if ($addr.Count -ne $watch.Count) { throw '缺少计数符号，请选配套的板级 ELF。' }
  $previous = $null
  foreach ($sample in 1..3) {
    if ($sample -gt 1) { Start-Sleep -Seconds 2 }
    $argsRead = @('-score','-halt')
    foreach ($n in $watch) { $argsRead += @('-r32',$addr[$n],'4') }
    $txt = (Call-St ($hot + $argsRead + @('-r32','0xE000ED28','4','-r32','0xE000ED2C','4','-run','-score'))) -join "`n"
    if ([regex]::Matches($txt,'(?im)^\s*Core is running\s*$').Count -lt 2) { throw '采样前后未确认运行；先查 -score。' }
    if ((Read-HexWord $txt '0xE000ED28') -ne 0 -or (Read-HexWord $txt '0xE000ED2C') -ne 0) { throw 'CFSR/HFSR 非零，停止判断并保留现场。' }
    $now = [ordered]@{}; foreach ($n in $watch) { $now[$n] = Read-HexWord $txt $addr[$n] }
    [PSCustomObject]$now | Format-List
    if ($null -ne $previous) { foreach ($n in $watch) { if ($now[$n] -le $previous[$n]) { throw "第 $sample 次采样：$n 未前进" } } }
    $previous = $now
  }
  '通过：两个连续区间内，tick、8 个线程和队列收发都前进。'
}

该看到什么：_tx_timer_system_clock 约每秒增加 100；thread_0_counter 到 thread_7_counter 全部增加，队列已发送、已接收数也分别增加，不要求同一时刻相等。对照历史 C5 的三组真机计数和实测边界。这个短测验证 Demo，不等于全内核覆盖或车规认证。

卡住时，先区分是哪一层

有电、LD1 在闪，但找不到“ST-LINK 串口”
不需要 COM 号。用数据线接 CN1，退出占用探针的工具，再执行 & $cli -l st-link。连探针都列不出才检查线、USB 口和 Windows 驱动；能列出但 SWD 连不上再核对板型、供电和调试连接。不要因此擦除芯片。
提示 Wrong ST input / 找不到 core_cm4.h
确认是第 1 步的 X-CUBE-AZRTOS-G4 v2.0.0；不要把 Drivers、外层 ZIP 目录或整套 STM32CubeG4 固件包当作 --cube-root。启动文件、系统文件和链接脚本会对哈希，不能随意换成别的示例。
提示 Changed threadx_core input / Wrong core file set
这是原始字节和文件集合检查。不要重排、全目录转换换行或在 threadx_core 里输出对象文件；在新的完整副本里重试，保留你已有修改。不要关掉哈希检查。
提示编译器不匹配，或自己建工程后报重复定义
先看 & $gcc --version，再回到第 3 步的板级入口。不要把 ST 启动与通用 crt0 同时链接、不要同时链接两个 MISRA 提供者，也不要自己再 -D 配置头已定义的开关。
校验通过但串口无输出，或只有 tick 在变
这个通用 Demo 不调用 UART、不做 LED 心跳。用对应 ELF 看第 6 步全部计数；若只有 tick 在走，先保留可重复的样本和 PC、故障寄存器，别把“有时钟”等同于“应用都正常”。
