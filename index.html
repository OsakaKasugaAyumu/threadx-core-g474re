阅读口径

同一个文件，为什么有三个行数？

以 tx_port.h 为例。三处都统计有效行，但源码并非同一版：

历史上游 · 422 行
历史第 01 层导读记录固定版本原件的计数。全量目录另列 Demo、构建和启动支撑，不把它们算作内核。
裁前学习版 · 423 行
main/tx_port.h 已接入 项目的 autoconf.h；原 214 个文件各多一条有效包含指令，不再与历史原件逐字节相同。
当前裁剪版 · 110 行
裁剪导读对应 threadx_core/tx_port.h。只用 423 → 110 算裁剪量；没被 Demo 调用的 API 不因此删除。

收录 208 份内核与端口、6 份 Demo 及支撑、1 份项目配置。原 214 份中的 81 已用 / 133 未直接用 是历史构建与链接标记，不是实板覆盖率；第 215 份配置头单列。

C5 · 哪个镜像上过板
核对历史 G474RE 镜像的读回结果和线程计数，见实板采样摘要。教程在其他目录生成的可移植镜像不冒用这次实测。
